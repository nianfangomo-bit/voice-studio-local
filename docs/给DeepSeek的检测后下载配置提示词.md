## 先确认你的能力

请明确你是否有本机终端、文件读写、联网下载权限；没有就给我人工步骤，不假装执行。不要把本机诊断成功当成下载、安装权限也已具备。

## 第一阶段：只读检测

1. 找到声线工作室实际安装目录、软件版本和已选环境，不读取或发送 session.json 的令牌。
2. 检测 Windows 版本及架构、所有显卡的型号/计算架构/显存、驱动版本、目标磁盘空间。信息缺失标为未知，不按型号名称猜。
3. 使用软件配置的 Python 检查 torch、torchaudio、CUDA 和核心依赖。不要用系统 Python 的结果代替。
4. 如显卡空闲，在用户知情下执行短时矩阵和 FFT 运算并同步。不要训练；is_available=True 和矩阵成功都不能证明 FFT 或训练可用。
5. 已有环境确实可用时保留它，不为“最新版”重下环境；只因 CPU 转写不要重装。

## 第三阶段：独立准备

1. 独立目录下载、校验、解压，不覆盖旧软件或 engine/runtime，不移动录音、校对、作品和权重。
2. 下载支持断点续传，但续传后必须全文件校验。校验失败不能继续解压或执行。
3. 核对实际解压结构、Python 和依赖版本及许可证，不假定包中必然是某个 torch/Python 版本。
4. 验证应用服务所需依赖与引擎所需依赖。缺少依赖先报告精确清单、来源与版本方案，不能直接 pip install --upgrade。
5. 软件若没有“Python 完整路径”配置入口，说明仍是旧发行版本，停止自动接入并向开发者索取适配版本。不要因为仓库有新源码就认为安装包已更新，不自行改 launcher.py。
6. 新版通过环境设置保存可信引擎、Python 和 FFmpeg 路径。任务运行时不得切换。记录原配置并备份数据库；服务本身更换 Python 需要关闭原服务再启动，不只是刷新浏览器。

## 第四阶段：分项验收

基础运算通过后，使用用户授权声线做短段新文本配音。完整训练另征得用户同意，复用已有校对素材，记录每阶段结果、两份模型权重、未见文本试听、重启复用、单句重做和字幕导出。

切换环境后的旧失败任务可能保留旧环境快照；不要直接反复重试旧任务。新建一次任务，先核对任务实际调用的 Python 和引擎。

结果分别写“真实通过 / 模拟测试 / 未测试 / 失败”。出现问题保留日志、检查点和素材，退回旧配置，不清空 data，不删除模型。个人录音、模型、数据库和文案不得上传到 GitHub。
