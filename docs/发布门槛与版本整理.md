# 现在距离正式发布还差什么

核对日期：2026-11-05。1.0.2-rc.1 已公开供测试下载；“已经能下载”和“可以宣称稳定、面向小白交付”不是一回事。

## 剩下的验收要做什么

| 事项 | 当前证据／缺口 | 完成标准 |
| --- | --- | --- |
| 新版真实核心流程 | 安装、依赖和文件校验通过，但本版未跑完训练与配音 | 在最终包上用授权录音完成切分、校对、训练、新文案试听、保存声线、重启复用、WAV/SRT 导出 |
| 另一台电脑与离线 | 尚未完成；开发机结果不能代表舍友电脑 | 从公开附件下载，记录机器和驱动，不借开发环境；用户确认断网后实际尝试核心流程 |
| 失败与恢复 | 有源码回归测试，不等于新版包端到端验证 | 测试项目验证取消、失败、重启、单句重做与字幕重算，旧结果保留；升级使用备份副本，不碰唯一原件 |
| 初次使用 | 原说明混有旧版内容，容易下载错包 | 新手只看到一个主入口，能按教程独立完成短文案；记录卡住的位置，不由助手暗中修环境掩盖问题 |
| 素材与标识 | 声音授权由用户提供；封面角色权利待确认；法定标识未验收 | 补齐封面权利依据或换权利清晰的素材；评估实际分发／服务模式的标识义务，若适用则落实技术方案，不以声明替代 |
| 分发与维护 | 固定版本许可材料已保留，未做独立法律／安全审计，安装器未签名 | 复核本次实际组件的许可材料和安全风险，清楚列出剩余限制；签名可作为后续完善项，不能假称已签名 |

一台额外电脑通过也不是所有机器兼容证明。发现阻断问题先修复、发新的 rc，并复测受影响路径；不要为了去掉“测试版”字样降低标准。

目前未删除任何版本。仓库首页已将新版作为唯一新手入口，旧版说明转入历史用途。

## 后续版本如何发

- 有代码或包内容修复：发布 `1.0.2-rc.2` 等新候选，保留已公开 rc.1 附件和哈希。
- 验收门槛满足后：发布 `1.0.2` 稳定版，版本、标签、清单、下载脚本一致；若重新构建，需核对新产物及受影响路径，不能只把 rc 文件改名。
- 这次新手教程与授权说明属于仓库文档更新，不改已发布 ZIP 的内容和摘要。旧包内部不会自动获得这些新文档；发布页面提供新版文档入口，下一次打包再纳入。
- 标准：一个推荐下载入口，一份新手教程，一份同版本验收记录，一份已知限制；历史记录可查、回退方式明确。
